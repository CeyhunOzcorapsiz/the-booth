# Ghost Play Studio

**See the run behind the goal.** A working football storytelling prototype that surfaces off-ball movement, connects it to measured positional evidence, and renders it as an interactive tactical replay.

Built for the Microsoft × Premier League **Inside the Game** hackathon. This is an initial prototype, not a completed submission or an official Premier League product.

## Run locally

Requires Node.js 22 or newer. No package installation or external assets are needed.

```sh
npm start
```

Open **http://localhost:3210**. Start playback, jump to a key moment, click an evidence card, switch between fan/analyst and Turkish/English, ask a supported question, or export the data and recap.

```sh
npm test
npm run check
npm run data -- 42
```

## What works

- Three synthetic 16-second sequences: decoy run, third-man run, pressing trap.
- 22 fictional players and a ball on a 105 × 68 m pitch; deterministic 10 Hz tracking with seeded position variation.
- Server-side measurements: lane clearance, player displacement, receiver separation, nearby pressers, and event-chain checks.
- Scrubbable 2D replay, tracking trails, tactical overlays, evidence-to-time links, two audiences and two languages.
- Local evidence-bounded question handling and downloadable structured moment recaps.
- Optional Microsoft Foundry broadcast editor + independent reviewer, with validation and an explicit local fallback.
- Real-time SSE frame/event endpoint. The interactive replay preloads the sequence for responsive seeking; it does not pretend to be a live match feed.

## Synthetic data statement

All players, clubs, positions and match events are generated by `lib/football.mjs`. No real Premier League data, third-party match footage, team crests, or copyrighted music is included. The crests and pitch are code-generated. Existing open datasets have not been copied or renamed.

The generator starts from authored tactical scenarios and interpolates trajectories. Seeds add small spatial variations, not independently learned match behaviour. This is a **scenario generator**, not a calibrated full-match physics engine. More varied unseen scenarios and expert review are needed before generalization claims.

Three ready-to-inspect datasets are in `data/`. Regenerate them with `npm run data -- 42` or choose a different seed.

Each detector receives tracking and events, never an intended-pattern label from a training target. The scenario ID selects the relevant detector; automatic discovery of arbitrary tactical patterns is not implemented. Numerical measurements come from coordinates. Tests include frozen and perturbed positions and missing event chains to reject unsupported patterns. Ground-truth scenario scripts still introduce design assumptions.

Lane clearance means minimum defender-to-fixed-line-segment distance. It is not a learned pass-success probability. Displacement is endpoint displacement, not cumulative distance travelled. No xG, player intent, causality, or calibrated confidence is claimed.

## Optional Microsoft Foundry integration

Copy `.env.example` to `.env` and set:

```dotenv
AZURE_AI_ENDPOINT=https://YOUR-RESOURCE.services.ai.azure.com/models
AZURE_AI_API_KEY=YOUR_KEY
AZURE_AI_MODEL=YOUR_DEPLOYMENT_NAME
```

Restart the server. The endpoint must support the Microsoft Foundry model inference Chat Completions API, JSON output, `temperature`, and `max_tokens`. Not all model deployments support identical parameters. API version defaults to `2024-05-01-preview` and can be overridden.

Reference: https://learn.microsoft.com/en-us/rest/api/microsoftfoundry/model-inference/get-chat-completions/get-chat-completions

The server sends measured facts to an editor model, validates its evidence IDs, then sends the draft and facts to an independent reviewer. A rejected draft, timeout, unsupported model configuration, or network error falls back to clearly labelled local templates. Review is a model check, not a mathematical guarantee. No model call runs without configuration, and keys never reach the browser. The UI distinguishes **configured** from **actually used**.

Without credentials, the application uses deterministic geometry, rule-based verification and authored narrative templates. It must not be presented as a running AI agent system in that mode. Live Azure calls require separate validation; mocked tests verify adapter behaviour only.

## HTTP interface

| Endpoint | Purpose |
|---|---|
| `GET /api/health` | Health and configuration presence, no credentials |
| `GET /api/scenarios` | Sequence list |
| `GET /api/match/decoy?seed=42` | Tracking, events, measurements and evidence |
| `GET /api/export/decoy?seed=42` | Download synthetic dataset |
| `GET /api/stream/decoy?seed=42` | SSE frames/events at 10 Hz; closes on completion |
| `POST /api/narrative` | `{id, seed, mode, lang}` |
| `POST /api/ask` | Same selection plus `question` |
| `POST /api/recap` | Structured recap and timed evidence |

Scenario IDs: `decoy`, `third-man`, `press`. Modes: `fan`, `analyst`. Languages: `tr`, `en`.

## Deployment

A Dockerfile is included for Azure Container Apps or another container host. Use `HOST=0.0.0.0` in the container and expose port 3210. Keep credentials in the hosting provider's secret store. Before a public launch, add authentication, per-user rate limits, usage budgets and production observability. The initial server limits concurrent AI work and request sizes but is designed as a local demo.

0–15s: show the goal and ask who opened the space. 15–50s: replay the run and follow the evidence cards. 50–75s: show the lane-clearance measurement and analyst mode. 75–95s: switch language and ask about the moment. 95–115s: generate a recap, show the actual Foundry editor/reviewer trace, and close with the synthetic-data statement.
